🟢 API 6 — Sistema de Reservas de Salas

Sistema de reservas para salas de reuniones

Una empresa tiene varias salas que sus empleados pueden reservar para reuniones. Cada reserva tiene una fecha, hora, duración, estado y costo.

Reglas

Empleado será el modelo utilizado para autenticación.

El JWT debe identificar al empleado que crea la reserva.

El empleadoId debe salir del JWT, no del body.

Una reserva nueva comienza con:

estado = "pendiente"

Los estados permitidos son:

pendiente
confirmada
en_curso
finalizada
cancelada

La fecha de la reserva no puede ser anterior al día actual.

horaFin debe ser posterior a horaInicio.

La duración debe calcularse automáticamente:

duracion = horaFin - horaInicio

El costo depende de la duración:

costo = duracion × precioPorHora

Puedes utilizar un precio fijo definido por el sistema, por ejemplo:

precioPorHora = 500

Una reserva creada comienza como pendiente.

Solo el coordinador puede confirmar una reserva.

Un empleado solamente puede modificar sus propias reservas.

Una reserva cancelada no puede volver a confirmada.

Una reserva finalizada no puede modificarse.

Una reserva solamente puede pasar a en_curso cuando llegue su fecha/hora.

Una reserva en_curso puede pasar a finalizada.

No se puede eliminar una reserva finalizada.

No pueden existir dos reservas para la misma sala en horarios que se superpongan.
